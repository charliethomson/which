# AGENTS

- **[`README.md`](README.md) is the front door.** Change behaviour it describes (a command,
  the layout, what's generated, what's still a stub) and update it in the same commit. Ran a
  command from it that didn't work? Fix it before reporting back.
- **[`SHORTCUTS.md`](SHORTCUTS.md) before environment recon.** Anything about the *running
  system* rather than the source: check it first. After recon that cost more than a couple
  of commands, append the route you found (endpoint, command, mechanism), never the reading.

## Repo-specific overrides

- **Two crates, two archetypes.** `libwhich/` is the library this repo is for. `which/` is a
  [CLI tool](https://standards.thmsn.dev/d/archetypes/cli-tool) over it: `product_name!`
  `dev.thmsn.which.cli` published with `set_global()`, `build.rs` deriving the version and
  embedding `libbuildinfo` (`--build-info`), completions generated by `--completions
  <shell>` (a flag, since a positional `completions` would be a program name), and the
  registry's install manifest at `which/packaging/install.json`. It is published to
  `apps.dev.thmsn.dev` as product `dev.thmsn.which`, app `cli`, binary `which`.
- **CI is kiln on Woodpecker, push-only.** `.kiln/` is the source; `.woodpecker/` is
  generated from it and never hand-edited ([ci-cd](https://standards.thmsn.dev/d/ci-cd)).
  `rust.ci` is libci's template without the coverage job (a library has no floor).
  `rust.ci-matrix` runs clippy and the tests natively on the Mac and the Windows agent,
  plus the `no-default-features` build on Linux. `cli.release` builds the binary on the
  Mac (`darwin-arm64`) and the Windows agent (`windows-amd64`), attaches each to one
  draft version, and a Linux job finalizes it. Nothing runs on pull requests: `.kiln/`
  depends on private kiln and libci, so the repo declares the `ssh_key` checkout key and
  kiln makes it push-only. `emit` never deletes: a pipeline renamed or removed here leaves
  an orphan in `.woodpecker/` that has to be deleted by hand.
- **What Woodpecker needs set by hand**, since the files cannot say it: the repo enabled
  and marked **trusted** (the Linux jobs mount cache volumes under
  `/var/lib/woodpecker-cache/which/`); the secrets `ssh_key` (a deploy key that can read
  this repo, kiln and libci: the native agents clone over ssh with it), `registry_token`
  and `registry_repo_token`, all with `pull_request` off their event lists; "cancel
  previous pipelines" on for push and manual; a macOS agent labelled `os: macos` and a
  Windows agent labelled `os: windows`, both on the tailnet (the registry resolves nowhere
  else), with rustup installed for a user on each.
- **Versioning is `0.0.<count>` until the first tag.** `cli.release` uses
  `Version::derive_untagged_ok` because the repo has never been tagged. Tag `v0.1.0`, then
  switch `.kiln/src/main.rs` to `Version::derive` so a failed tag fetch can no longer
  publish below the live version. The workspace `version` in `Cargo.toml` is a placeholder
  ([versioning](https://standards.thmsn.dev/d/versioning)).
- **No `.cargo/config.toml`.** The library never logs an error as a `valuable` field, so it
  does not need `tracing_unstable`, and it has no private deps.
- **`which.c` is the oracle.** The FreeBSD source at the repo root defines the lookup and
  validation semantics on Unix. A behaviour change is checked against it first; Windows has
  no reference and follows `cmd.exe` (`PATHEXT`).
- **Tests never touch the environment.** `which_in` and `search_paths_from` exist so the
  logic is tested with directories handed in. Do not add a test that sets `PATH`: the suite
  runs multi-threaded and such a test races every other one.
